# Лабораторна робота №6. Абстрактні класи та інтерфейси

Варіант 11. Мирончук

## Опис

Інтерфейс `IComparer<T>` з методом `int Compare(T x, T y)`.
Реалізації для `string`:
- `StringLengthComparer` — порівнює рядки за довжиною;
- `AlphabeticalComparer` — порівнює рядки за алфавітом.

Абстрактний клас `FileProcessor`:
- абстрактні методи `ReadFile(string path)` і `ProcessContent()`;
- конкретний метод `WriteResult(string path)`.

Нащадки:
- `LogFileProcessor` — залишає рядки з ERROR та WARN;
- `ConfigFileProcessor` — прибирає порожні рядки та коментарі.

У `Program.cs` створено колекції обох типів і виконано поліморфні виклики.

Запуск: `dotnet run`

## Контрольні питання

**1. У чому основна відмінність між абстрактним класом та інтерфейсом?**
Інтерфейс описує лише контракт. Абстрактний клас може містити готовий код, поля й конструктори. Від одного класу можна успадкуватись лише раз, а інтерфейсів реалізувати можна багато.

**2. Коли доцільно використовувати абстрактний клас, а коли інтерфейс?**
Абстрактний клас — для тісно пов'язаних класів зі спільною логікою (наприклад, `FileProcessor` з однаковим `WriteResult`). Інтерфейс — коли різні класи мають уміти те саме (наприклад, `IComparer` для порівняння рядків, чисел, дат).

**3. Чи може клас успадковувати від кількох абстрактних класів? А реалізовувати кілька інтерфейсів?**
Від кількох класів успадковувати не можна, лише від одного. Кілька інтерфейсів реалізовувати можна.

**4. Як вони сприяють поліморфізму та гнучкості архітектури?**
Код працює з абстракцією (`IComparer<string>` або `FileProcessor`), а не з конкретним класом. Нову реалізацію можна додати без змін у коді, який її використовує. Програму легше розширювати й тестувати.
