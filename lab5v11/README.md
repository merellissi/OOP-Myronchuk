# Лабораторна робота №5. Поліморфізм

**Проєкт:** lab5v11 (варіант 11, Мирончук)
**Тема:** Поліморфізм: динамічне зв'язування та перевизначення методів

## Опис ієрархії

Базовий клас `Building` має поле `Address` і віртуальний метод `GetPurpose()`.
Похідні класи перевизначають цей метод через `override`:

- `House` (поле `NumRooms`): житловий будинок
- `Office` (поле `NumFloors`): офіс
- `Shop` (поле `ProductType`): магазин

Кожен клас має конструктор для ініціалізації полів.

У методі `Main` створено `List<Building>`, до якого додано об'єкти всіх
похідних класів. У циклі для кожного об'єкта викликається `GetPurpose()`,
і виконується реалізація, що відповідає фактичному типу об'єкта.

**Агрегація:** оскільки метод нічого не повертає, зібрано підсумковий список
призначень усіх будівель і підраховано кількість викликів.

## Контрольні питання

**1. Що таке поліморфізм і як він реалізується в C# за допомогою virtual та override?**
Поліморфізм - це здатність об'єктів різних класів по-різному реагувати на
однаковий виклик методу залежно від їхнього фактичного типу. У C# базовий клас
позначає метод модифікатором `virtual`, а похідний клас надає власну реалізацію
за допомогою `override`.

**2. Поясніть поняття динамічного зв'язування. Чим воно відрізняється від статичного?**
Динамічне зв'язування - це визначення того, який метод викликати, під час
виконання програми за фактичним типом об'єкта. Статичне зв'язування відбувається
на етапі компіляції за типом змінної (так працюють звичайні, не віртуальні методи).

**3. Наведіть приклад, як поліморфізм дозволяє писати більш гнучкий та розширюваний код.**
Якщо додати новий клас `Warehouse : Building` з `override GetPurpose()`, то цикл
у `Main` не потрібно змінювати: він автоматично викличе метод нового класу.

**4. Які переваги дає використання колекцій базових типів для роботи з поліморфними об'єктами?**
Різні об'єкти зберігаються в одній колекції та обробляються одним циклом. Код не
залежить від конкретних класів, його легко розширювати, а дублювання коду менше.
