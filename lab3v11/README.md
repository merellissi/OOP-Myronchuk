# Лабораторна робота №3

**Тема:** Життєвий цикл об'єкта та керування ресурсами  
**Варіант:** 11

## Опис

Клас `CryptoStream` імітує криптографічний потік і реалізує `IDisposable` за патерном Dispose:

 поля `_algorithm`, `_isStreamOpen`, `_disposed`;
 метод `Encrypt(string data)`;
 `Dispose()`, `Dispose(bool disposing)` та деструктор `~CryptoStream()`.

У `Main` показано три сценарії: `using`, явний виклик `Dispose()` і деструктор через `GC.Collect()`.

Контрольні питання
1. З яких етапів складається життєвий цикл об'єкта?
Створення (пам'ять у купі та конструктор), використання, збирання сміття (коли посилань більше немає), фіналізація (опціонально, деструктор).
2. Чим відрізняються керовані та некеровані ресурси?
Керовані (пам'ять .NET-об'єктів) автоматично звільняє GC. Некеровані (файлові дескриптори, з'єднання з БД, мережеві потоки) потребують явного звільнення.
3. Для чого потрібен інтерфейс IDisposable?
Це стандартний спосіб явно звільняти ресурси: він містить метод Dispose(), який викликається вручну або через using.
4. Що робить оператор using?
Гарантує виклик Dispose() після виходу з блоку, навіть якщо всередині виник виняток.
5. Що таке патерн Dispose?
Поєднання Dispose(), захищеного методу Dispose(bool disposing) та деструктора для надійного звільнення ресурсів.
6. Навіщо потрібен параметр disposing?
true означає виклик із коду програми: звільняємо керовані й некеровані ресурси. false означає виклик із деструктора: звільняємо лише некеровані, бо керовані об'єкти могли вже бути знищені.
7. Навіщо потрібен деструктор, якщо є Dispose()?
Він страхує на випадок, коли програміст забув викликати Dispose().
8. Для чого GC.SuppressFinalize(this)?
Після Dispose() деструктор уже не потрібен, і ця команда забороняє GC викликати його повторно.
9. Навіщо поле _disposed?
Щоб повторний виклик Dispose() не звільняв ресурси вдруге.
10. Для чого GC.Collect() і GC.WaitForPendingFinalizers() у лабораторній?
GC.Collect() примусово запускає збирання сміття, щоб продемонструвати роботу деструктора. GC.WaitForPendingFinalizers() чекає, поки всі деструктори завершаться.
