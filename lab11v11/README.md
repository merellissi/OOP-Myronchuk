## 1. Сутності та тестові дані

Дані мають три рівні вкладеності: **подія → учасники → квитки**.

```csharp
public class Event       { int Id; string Name; List<Participant> Participants; }
public class Participant { int Id; string Name; List<Ticket> Tickets; }
public class Ticket      { int Id; string Type; decimal Price; }
```

**Тестові дані:** 9 подій, 21 учасник, 26 квитків. В одних подій 1 учасник, в інших 3; один учасник може мати від 1 до 2 квитків (наприклад, «3 дні» + «Кемпінг»). Є безкоштовний квиток (0 грн), щоб перевірити, що сума рахується коректно. Номери квитків видаються автоматично допоміжним методом `T(type, price)`.

## 2. SelectMany: усі квитки всіх учасників усіх подій в одному списку

```csharp
List<Ticket> allTickets = events
    .SelectMany(e => e.Participants)
    .SelectMany(p => p.Tickets)
    .ToList();
```

Перший `SelectMany` «розгортає» події в один список учасників (21), другий — учасників в один список квитків (26).

Щоб у результаті було видно, до якої події й якого учасника належить квиток, використано перевантаження `SelectMany` з **resultSelector**:

```csharp
events
    .SelectMany(e => e.Participants, (e, p) => new { Event = e, Participant = p })
    .SelectMany(x => x.Participant.Tickets,
                (x, t) => new TicketInfo(x.Event.Name, x.Participant.Name, t.Id, t.Type, t.Price))
```

Те саме в синтаксисі запитів (кілька `from` поспіль компілюються в `SelectMany`):

```csharp
from e in events
from p in e.Participants
from t in p.Tickets
select new TicketInfo(e.Name, p.Name, t.Id, t.Type, t.Price)
```

**Результат:** список із 26 квитків з назвою події та ім'ям учасника (повний вивід — у розділі 6). Обидва синтаксиси дали однаковий результат.

**Select vs SelectMany** на тих самих даних:

| Оператор | Кількість елементів | Тип елемента |
|---|---:|---|
| `events.Select(e => e.Participants)` | 9 | `List<Participant>` — список списків |
| `events.SelectMany(e => e.Participants)` | 21 | `Participant` — один плаский список |

Додатково результат `SelectMany` згруповано за типом квитка (`GroupBy`): найбільше доходу дали квитки VIP (6 000 грн) і «3 дні» (5 600 грн).

## 3. Пагінація: події по 2 на сторінку

Пагінацію реалізовано як універсальний метод розширення для будь-якої колекції:

```csharp
public static IEnumerable<T> Paginate<T>(this IEnumerable<T> source, int pageNumber, int pageSize)
{
    if (pageNumber < 1) throw new ArgumentOutOfRangeException(nameof(pageNumber));
    if (pageSize < 1)   throw new ArgumentOutOfRangeException(nameof(pageSize));

    return source.Skip((pageNumber - 1) * pageSize).Take(pageSize);
}

public static int PageCount<T>(this IReadOnlyCollection<T> source, int pageSize) =>
    (int)Math.Ceiling(source.Count / (double)pageSize);
```

- `Skip((pageNumber - 1) * pageSize)` пропускає елементи попередніх сторінок;
- `Take(pageSize)` бере не більше `pageSize` елементів;
- кількість сторінок = ⌈9 / 2⌉ = **5**, остання сторінка неповна (1 подія);
- запит сторінки 6 (поза межами) повертає порожній результат без помилки.

| Сторінка | Skip / Take | Події |
|---:|---|---|
| 1 | Skip(0).Take(2) | IT Conference Rivne, Концерт гурту «Антитіла» |
| 2 | Skip(2).Take(2) | Опера «Наталка Полтавка», Фестиваль вуличної їжі |
| 3 | Skip(4).Take(2) | .NET Meetup, Рок-фестиваль |
| 4 | Skip(6).Take(2) | Різдвяний ярмарок, Симфонічний концерт |
| 5 | Skip(8).Take(2) | Гейм-джем |
| 6 | Skip(10).Take(2) | — (0 подій) |

## 4. Метод розширення `TotalTicketRevenue()`

```csharp
public static decimal TotalTicketRevenue(this IEnumerable<Event> events) =>
    events
        .SelectMany(e => e.Participants)
        .SelectMany(p => p.Tickets)
        .Sum(t => t.Price);

public static decimal TotalTicketRevenue(this Event ev) =>
    new[] { ev }.TotalTicketRevenue();
```

Метод оголошено в статичному класі, а перед першим параметром стоїть `this`. Тому він викликається як «рідний» метод колекції: `events.TotalTicketRevenue()`. Друге перевантаження рахує дохід однієї події (`ev.TotalTicketRevenue()`) і використовує першу реалізацію, без дублювання логіки.

**Приклади використання:**

| Виклик | Результат |
|---|---:|
| `events.TotalTicketRevenue()` | 23 250 грн (збігається з `allTickets.Sum(t => t.Price)`) |
| `events.Where(e => e.Name.Contains("концерт", …)).TotalTicketRevenue()` | 7 400 грн |
| `events.Paginate(1, 2).TotalTicketRevenue()` | 9 300 грн |
| `events.OrderByDescending(ev => ev.TotalTicketRevenue()).Take(3)` | Рок-фестиваль (7 400), Концерт гурту «Антитіла» (5 300), IT Conference Rivne (4 000) |
| `new List<Event>().TotalTicketRevenue()` | 0 грн |

Метод розширення працює в ланцюжку з `Where`, `OrderByDescending` і власним `Paginate`, так само як вбудовані оператори LINQ.

## 5. Відповіді на контрольні питання

**1. Для чого використовується `SelectMany`? Чим він відрізняється від `Select`?**
`SelectMany` перетворює кожен елемент на колекцію і об'єднує всі ці колекції в одну пласку послідовність (flattening). `Select` перетворює кожен елемент на одне значення, і якщо це значення — колекція, результатом буде «колекція колекцій». У нашому прикладі `events.Select(e => e.Participants)` дає 9 списків учасників (`IEnumerable<List<Participant>>`), а `events.SelectMany(e => e.Participants)` — 21 учасника в одному списку (`IEnumerable<Participant>`). `SelectMany` потрібен, коли треба працювати з усіма вкладеними елементами разом: порахувати суму всіх квитків, згрупувати їх за типом, знайти найдорожчий. У синтаксисі запитів йому відповідають кілька `from` поспіль.

**2. Як реалізувати пагінацію за допомогою LINQ? Які методи використовуються?**
Пагінація реалізується методами `Skip` і `Take`: `collection.Skip((pageNumber - 1) * pageSize).Take(pageSize)`. `Skip(n)` пропускає перші n елементів, `Take(n)` бере наступні n. Кількість сторінок дорівнює `Math.Ceiling(count / (double)pageSize)`. Обидва методи відкладені й не падають, якщо елементів менше, ніж запитано: остання сторінка буде неповною, а сторінка поза межами — порожньою. Для стабільного результату колекція має бути впорядкованою (тут — за порядком додавання; для БД потрібен `OrderBy`). При роботі з базою даних через `IQueryable` `Skip/Take` перетворюються на `OFFSET … FETCH` у SQL, і сервер повертає лише одну сторінку.

**3. Поясніть концепцію методів розширення. Як вони інтегруються з LINQ?**
Метод розширення — це статичний метод статичного класу, перший параметр якого позначено `this`. Він дозволяє «додати» метод до існуючого типу (навіть до інтерфейсу чи чужого класу) без зміни його коду й без наслідування. Викликається він через крапку, як звичайний метод екземпляра: `events.TotalTicketRevenue()` компілюється у `EventExtensions.TotalTicketRevenue(events)`. Сам LINQ побудований саме так: `Where`, `Select`, `OrderBy` — це методи розширення для `IEnumerable<T>` з класу `System.Linq.Enumerable`. Тому власні методи розширення для `IEnumerable<T>` вбудовуються в LINQ-ланцюжки нарівні зі стандартними: `events.Where(...).Paginate(1, 2).TotalTicketRevenue()`.

**4. Наведіть приклад власного методу розширення для `IEnumerable<T>` та поясніть його призначення.**
`Paginate<T>` з цієї роботи — узагальнений метод розширення для будь-якої колекції:
```csharp
public static IEnumerable<T> Paginate<T>(this IEnumerable<T> source, int pageNumber, int pageSize) =>
    source.Skip((pageNumber - 1) * pageSize).Take(pageSize);
```
Він інкапсулює формулу пагінації (яку легко записати з помилкою, наприклад забути `- 1`) і перевірку аргументів, тому в коді достатньо написати `events.Paginate(3, 2)`. Метод узагальнений, тож працює і з подіями, і з квитками, і з будь-якими іншими даними. Доменний приклад — `TotalTicketRevenue()` для `IEnumerable<Event>`: він ховає за однією зрозумілою назвою бізнес-правило «дохід = сума цін усіх квитків усіх учасників».
