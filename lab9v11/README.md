# lab9v11 — Система кешування

Лабораторна робота №9 з ООП. Варіант 11. Виконав: Мирончук.

## Що робить кожна колекція

| Колекція | Підзадача | Основні операції |
|---|---|---|
| `HashSet<string>` | Унікальні ключі кешу, швидка перевірка наявності ключа (cache hit / miss) | `Add`, `Contains`, `Remove` |
| `Queue<string>` | Черга на видалення за принципом LRU: на початку черги найдавніше використаний ключ, він видаляється першим при переповненні | `Enqueue`, `Dequeue`, `Peek` |
| `Stack<string>` | Історія звернень до кешу (PUT / GET / MISS), остання дія зверху | `Push`, `Pop`, `Peek` |

## Запуск

```bash
dotnet run
```

## Приклад виводу

```
=== 1. HashSet<T>: унікальні ключі кешу ===
  Add("user:1") -> додано
  Add("user:2") -> додано
  Add("user:1") -> дублікат, ігноровано
  Add("page:home") -> додано
  Add("user:2") -> дублікат, ігноровано
  Унікальних ключів: 3
  Contains("page:home") = True
  Contains("page:about") = False
  Після Remove("user:1"): { user:2, page:home }

=== 2. Queue<T>: черга на видалення (FIFO) ===
  Peek() = A
  Dequeue() = A
  Dequeue() = B
  Dequeue() = C

=== 3. Stack<T>: історія звернень (LIFO) ===
  Peek() = C
  Pop() = C
  Pop() = B
  Pop() = A
  Висновок: Queue віддає A,B,C (FIFO), Stack віддає C,B,A (LIFO)

=== 4. Система кешування (ємність = 3) ===
  [PUT] Додано новий ключ 'a'
  [PUT] Додано новий ключ 'b'
  [PUT] Додано новий ключ 'c'
  Ключі (HashSet):       { a, b, c }
  Черга видалення (Queue): a -> b -> c  (перший буде видалений)
  Peek черги:            a

  Звертаємось до 'a' (він стає найновішим):
  [GET] Ключ 'a' знайдено (cache hit): 1
  Ключі (HashSet):       { a, b, c }
  Черга видалення (Queue): b -> c -> a  (перший буде видалений)
  Peek черги:            b

  Додаємо 'd' -> кеш повний, має піти найдавніший ('b'):
  [EVICT] Кеш повний -> видалено найдавніший ключ 'b'
  [PUT] Додано новий ключ 'd'
  Ключі (HashSet):       { a, d, c }
  Черга видалення (Queue): c -> a -> d  (перший буде видалений)
  Peek черги:            c

  Перевіряємо відсутній ключ:
  [GET] Ключ 'b' НЕ знайдено (cache miss)

  Оновлюємо існуючий ключ 'c':
  [PUT] Ключ 'c' вже є в кеші -> значення оновлено

  Історія звернень:
  Історія (Stack, зверху вниз): PUT c | MISS b | PUT d | GET a | PUT c | PUT b | PUT a
  Останнє звернення (Peek): PUT c
  [POP] Вилучено з історії: PUT c
  [POP] Вилучено з історії: MISS b
  Історія (Stack, зверху вниз): PUT d | GET a | PUT c | PUT b | PUT a

=== 5. Продуктивність: List.Contains vs HashSet.Contains ===
  Елементів: 50000, пошуків: 1000
  List<int>.Contains:    22 мс (знайдено 1000)
  HashSet<int>.Contains: 0 мс (знайдено 1000)
  Висновок: List шукає за O(n), HashSet в середньому за O(1).
```
